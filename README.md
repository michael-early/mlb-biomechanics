# MLB Biomechanics MVP

Implemented portfolio MVP for MLB quantitative roles: a reproducible Python pipeline that engineers pitching-biomechanics metrics, predicts pitch velocity, and bridges comparable pitch traits to on-field performance outcomes.

## Thesis

Public motion-capture data can be turned into interpretable biomechanical performance metrics that explain pitch velocity. Those metrics can then be connected to MLB performance analysis through a separate Statcast-style pitch-trait/outcome bridge.

The project is intentionally honest about public-data limits: OpenBiomechanics athletes are anonymized, so this MVP does **not** claim direct player-level matching to MLB outcomes.

## What Runs Today

- Downloads public OpenBiomechanics pitching point-of-interest metrics and metadata.
- Computes interpretable biomechanical pitching metrics:
  - sequencing efficiency
  - hip-shoulder separation score
  - kinetic-chain transfer score
  - lead-leg block score
  - lower-body force score
  - arm-speed score
  - release-consistency score
- Trains a NumPy ridge-regression model to predict `pitch_speed_mph`.
- Compares the model against a baseline mean predictor.
- Produces feature coefficients and permutation importance.
- Builds a Statcast performance bridge from a user-supplied Statcast CSV when present, otherwise from a clearly labeled generated Statcast-like sample.
- Writes a static HTML report and optional Streamlit dashboard entry point.
- Includes unit tests using Python's built-in `unittest`.

## Quickstart

```bash
cd /Users/mearly/dev/projects/mlb-biomechanics

# Optional but recommended: download public OpenBiomechanics CSVs.
PYTHONPATH=src python3 -m mlb_biomechanics download-data

# Build metrics, models, tables, and report.
PYTHONPATH=src python3 -m mlb_biomechanics build

# Run tests.
PYTHONPATH=src python3 -m unittest discover -s tests
```

Open the generated report:

```text
reports/mvp_report.html
```

Optional Streamlit app:

```bash
streamlit run app.py
```

If Streamlit is not installed, the static HTML report is the primary implemented artifact.

## Supplying Real Statcast Data

Export a Baseball Savant CSV and save it as one of:

```text
data/raw/statcast/statcast_sample.csv
data/raw/statcast/statcast.csv
```

The bridge expects pitch-level columns such as `pitch_type`, `release_speed`, `release_extension`, `pfx_x`, `pfx_z`, and outcome columns if available (`whiff`, `chase`, `hard_hit`, `run_value`). If those outcome columns are not present, the current bridge keeps the workflow running but the strongest portfolio version should use a curated Statcast export with explicit outcome flags.

## Resume Bullet

Built an end-to-end Python ML pipeline using public OpenBiomechanics pitching motion-capture data to engineer interpretable biomechanical metrics, predict pitch velocity with grouped validation, and connect comparable pitch traits to Statcast-style whiff/run-value outcomes through a portfolio report and dashboard entry point.

## Limitations

- OpenBiomechanics athletes are anonymized; no MLB player identity matching is attempted.
- The current checked-in MVP can run without real Statcast data by using a generated sample for the performance bridge.
- Results are associative and predictive, not causal.
- Injury diagnosis and medical risk prediction are out of scope.
